## 4-3. 판단 근거 회고 (AI 결과물 검증)

### 1. 그대로 쓴 것 (Accepted)
- 5단계 검증 파이프라인의 **처리 순서 원칙**(비용 저렴한 검증 먼저, 무거운 검증 나중) — 타당한 설계 원칙이라 판단해 수정 없이 채택.
- design.md 작성 시 AI가 자체적으로 내린 **F1-2(체크박스 자동저장) 최종 결정과 그 근거**(항목 수가 적어 일괄저장 이점이 낮음) — 별도 반려 없이 그대로 채택. 앞서 여러 차례 AI의 임의 판단을 반려/수정했던 것과 달리, 이번엔 근거가 합리적이라고 판단해 검증 후 승인.

### 2. 고쳐 쓴 것 (Modified)
- **ClamAV 처리 방식**: AI는 처음에 "응답지연 우려로 비동기(임시저장→스캔→반영) 검토"를 제안했으나, 과제 성격(인터뷰용 과제, 시간 제약)을 고려해 **동기 방식 + 구현 단순화**로 직접 결정해 반영 지시.
- **general.md 범위**: AI가 초안 작성 시 AI 활용 관련 내용을 general.md(시스템 정의 문서)에 섞어 넣었으나, 문서 역할이 맞지 않다고 판단해 제거 지시.

### 3. 버린 것 & AI 오류 수정 (Rejected & Caught Errors)
- **섹션 번호 중복 오류**: AI가 general.md 4번 항목을 정리하면서 "4-3(선택범위)"과 "4-3(제외범위)"를 중복 번호로 생성 → 직접 발견하고 수정 지시.
- **논리적 모순 방치**: ClamAV를 실제로 도입하기로 확정했음에도 AI가 만든 "제외 범위" 섹션에는 여전히 "바이러스 백신 연동 제외"라는 문구가 남아있었음 → 앞뒤가 맞지 않는 부분을 직접 짚어 삭제 지시.
- **과잉 차단 정책 (근거 없는 일반화)**: AI가 dotfile(`.env` 등)을 "확장자 없는 파일"과 동일하게 취급해 차단하도록 제안했으나, 이는 **파일명(레이블)과 실제 위험성을 혼동한 판단**이었음. `.env`라는 이름 자체가 위험을 의미하지 않는다는 근거를 들어 반려하고, 일반 확장자와 동일하게 정책 대조만 하도록 수정.
- **알고리즘의 자체 모순(AI가 스스로 포착 후 방치한 허점)**: AI가 제안한 4단계 확장자 판별 알고리즘은 "`.`이 하나도 없는 파일(`Makefile`)도 조각 1개로 처리되어 정책에 없으면 통과될 수 있다"는 허점을 AI 스스로 "주의" 문구로 남겼으나, 이를 바로 고치지 않고 "spec.md에서 추가 결정 필요"로 미뤄둔 상태였음 → 이 허점을 방치하지 않고 "`.` 유무를 최우선으로 먼저 판별"하는 5단계 알고리즘으로 직접 재작성해 반영 지시. **AI가 문제를 인지하고도 결론까지 밀어붙이지 않은 부분을 사용자가 마무리 지은 사례.**
- **문서 간 정합성 누락 (function.md ↔ spec.md)**: function.md에서 이미 "이중 확장자는 모든 후보를 각각 검사한다"고 확정했음에도, AI가 spec.md의 DB 스키마를 설계할 때는 `upload_file.extension`을 단일 값 컬럼으로만 설계해 두 문서 간 논리가 어긋났음. AI가 새 문서를 만들 때 이전 문서에서 확정한 규칙과의 정합성을 스스로 검증하지 않는다는 패턴을 확인 → 컬럼을 `extension_candidates`(후보 전체 보존) + `matched_extension`(차단 유발 값)로 분리하도록 직접 지적해 수정.

> 공통적으로, AI가 생성한 산출물을 그대로 채택하지 않고 **① 과제 원문 요구사항과의 정합성, ② 문서 내부의 논리적 일관성, ③ 문서 간(예: function.md ↔ spec.md) 상호 정합성, ④ 보안·정책 판단의 실제 근거 유무**를 기준으로 매번 검수한 뒤 반영 여부를 결정함. 특히 문서 개수가 늘어날수록(③) AI가 앞서 확정한 내용을 다음 문서에 자동으로 반영하지 못하는 경우가 반복적으로 나타나, **새 문서를 만들 때마다 이전 확정 문서를 다시 첨부하거나 명시적으로 대조 확인을 요구하는 습관**이 필요하다는 점을 확인함.
