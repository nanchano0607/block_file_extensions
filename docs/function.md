## 2. F1. 확장자 정책 관리

### F1-1. 고정 확장자 목록 조회
- **설명**: 화면 진입 시 고정 확장자 7개(`bat`, `cmd`, `com`, `cpl`, `exe`, `scr`, `js`)와 각 항목의 현재 차단 여부(체크 상태)를 DB에서 조회하여 표시한다.
- **트리거**: 화면 최초 진입 / 새로고침
- **연동 API**: `GET /api/policy/fixed-extensions` (예시, 상세는 spec.md)
- **표시 규칙**: DB에 저장된 값이 없는 고정 확장자는 **default unchecked**로 표시한다.

### F1-2. 고정 확장자 체크/해제
- **설명**: 사용자가 체크박스를 클릭하면 해당 확장자의 차단 여부를 즉시 DB에 반영한다.
- **트리거**: 체크박스 클릭
- **처리 방식**: 클릭 시점에 즉시 저장(자동 저장) — 별도의 "저장" 버튼 없이 토글 = 저장으로 간주한다. 
- **연동 API**: `PATCH /api/policy/fixed-extensions/{ext}`
- **예외 처리**:
  - 저장 실패(네트워크/서버 오류) 시 체크박스 상태를 이전 상태로 롤백하고 에러 메시지 표시 (상세 UI는 design.md)

### F1-3. 커스텀 확장자 목록 조회
- **설명**: 현재 등록된 커스텀 확장자 목록과 총 개수(`N/200`)를 조회하여 표시한다.
- **트리거**: 화면 최초 진입 / 추가·삭제 이후 갱신
- **연동 API**: `GET /api/policy/custom-extensions`
- **표시 규칙**: 고정 확장자 7개와 중복되는 값은 커스텀 목록에 표시하지 않는다 (등록 자체를 막음, F1-4 참고).

### F1-4. 커스텀 확장자 추가
- **설명**: 사용자가 입력창에 확장자를 입력하고 "추가" 버튼을 클릭하면 DB에 저장 후 목록에 즉시 반영한다.
- **트리거**: "추가" 버튼 클릭 (또는 Enter)
- **입력 검증 (클라이언트 1차)**:
  - 최대 20자
  - 빈 값 불가
  - 선행 `.` 자동 제거 또는 사용자가 `.`을 입력한 경우 정규화 (예: `.sh` → `sh`)
- **서버 검증 (2차, 최종 판단)**:
  - 최대 200개 초과 시 거부
  - 고정 확장자 7개와 중복 시 거부 (이미 고정 목록에서 관리되므로 커스텀 등록 불필요/혼란 방지)
  - 커스텀 목록 내 중복 시 거부
  - 특수문자/공백/유니코드 등 비정상 입력 정규화 또는 거부 (상세 규칙 spec.md)
- **연동 API**: `POST /api/policy/custom-extensions`
- **예외 처리**:
  - 200개 초과 시: "추가" 버튼 비활성화 + 안내 메시지
  - 중복 입력 시: 저장 없이 안내 메시지, 입력값 유지
  - 서버 오류 시: 에러 메시지, 목록 상태는 이전 상태 유지(낙관적 업데이트 금지 또는 롤백)

### F1-5. 커스텀 확장자 삭제
- **설명**: 목록의 각 항목 옆 `X` 클릭 시 DB에서 삭제하고 화면에서 즉시 제거한다.
- **트리거**: `X` 아이콘 클릭
- **연동 API**: `DELETE /api/policy/custom-extensions/{id}`
- **예외 처리**: 삭제 실패 시 항목을 목록에 복원하고 에러 메시지 표시

## 3. F2. 파일 업로드 처리

### F2-1. 파일 업로드 요청
- **설명**: 사용자가 파일을 선택/드래그하여 업로드를 요청한다.
- **트리거**: 파일 선택 + 업로드 버튼 클릭 (또는 선택 즉시 자동 업로드, design.md에서 확정)
- **클라이언트 1차 체크** (UX 개선 목적, 보안 목적 아님 — 최종 판단은 항상 서버):
  - 파일 크기 **10MB** 초과 여부 (서버 0단계와 동일 기준을 클라이언트에도 미리 적용해 불필요한 업로드 시도를 줄임)
  - 확장자 정책상 차단 대상인지 (현재 조회된 정책 기준, 참고용 표시)
- **연동 API**: `POST /api/upload` (multipart/form-data)

### F2-2. 6단계 파일 검증 파이프라인 (서버, 동기 순차 처리)
업로드된 파일은 아래 순서로 검증되며, **어느 한 단계에서라도 실패하면 즉시 중단**한다 (뒷 단계는 실행하지 않음 — 비용이 비싼 검증을 불필요하게 수행하지 않기 위함). MIME 검사는 최종 차단 판단에 관여하지 않고 로그 기록용으로만 사용한다 (2단계 참고).

| 순서 | 단계 | 판단 기준 | 실패 시 | 사용자 노출 메시지(카테고리) |
|------|------|-----------|---------|------------------------------|
| 0 | 파일 크기 검사 | 파일 크기가 **10MB**를 초과하는가 | 즉시 차단 | "파일 크기 제한을 초과했습니다" |
| 1 | 확장자 검사 | 파일명의 확장자가 정책(고정+커스텀) 차단 목록에 포함되는가. 확장자가 없는 파일은 무조건 차단. 이중/다중/연속 점 확장자는 "전체 분리 방식"으로 처리(아래 상세 참고) | 즉시 차단 | "허용되지 않는 파일 형식입니다" |
| 2 | MIME 검사 | 요청의 `Content-Type`이 확장자와 명백히 불일치하는가 | **차단하지 않음.** 불일치 시 로그만 기록(참고/모니터링용), 다음 단계로 항상 진행 | (해당 없음 — 통과 처리) |
| 3 | Magic Number 검사 | 파일 바이트 시그니처가 실제 파일 타입과 일치하는가. **1단계(확장자) 통과 여부와 무관하게, 파일의 실제 내용에 대한 최종 판단은 이 단계가 담당** | 즉시 차단 | "허용되지 않는 파일 형식입니다" |
| 4 | Parser 구조 검증 | (대표 타입 한정) 파일을 실제로 열어 구조가 유효한가 | 즉시 차단 | "파일을 처리할 수 없습니다" |
| 5 | ClamAV 악성코드 검사 | 알려진 악성코드 시그니처와 일치하는가 (동기 스캔) | 즉시 차단 | "악성코드가 탐지되었습니다" |

> 0단계(크기 검사)는 비용이 가장 저렴하면서도 대용량 파일이 뒷단계(특히 5단계 ClamAV 스캔)에서 불필요하게 자원을 소모하는 것을 막기 위해 파이프라인의 맨 앞에 둔다.

**1단계 확장자 판별 알고리즘 (공통 정규화 규칙)**
1. 파일명에 `.`이 **단 하나도 없으면** → 확장자 없는 파일로 즉시 분류, **차단** (예: `Makefile`, `README`).
2. 파일명에 `.`이 하나 이상 있으면, `.` 기준으로 전체 분리한다.
3. 분리된 조각 중 **빈 문자열은 전부 무시**한다 (연속된 점 `..`, 선행 점 `.env`, 후행 점 `abc.` 등으로 인해 발생하는 빈 조각 포함).
4. 3번을 거치고도 남은 조각이 **하나도 없으면** (예: 파일명이 `.` 하나뿐이거나 `...`뿐인 경우) → 확장자 없는 파일로 간주, **차단**.
5. 남은 조각이 **하나 이상 있으면** → 각 조각을 확장자 후보로 간주하여 정책(고정+커스텀 차단 목록)과 대조한다. **하나라도 차단 대상이면 전체 차단**한다.

이 알고리즘 하나로 아래 케이스가 모두 일관되게 처리된다.

| 예시 파일명 | 1단계 판정 (`.` 유무) | `.` 분리 결과 | 빈 문자열 제거 후 | 최종 판정 |
|---|---|---|---|---|
| `Makefile` | `.` 없음 → 즉시 차단 | (분리 안 함) | (분리 안 함) | **차단** |
| `README` | `.` 없음 → 즉시 차단 | (분리 안 함) | (분리 안 함) | **차단** |
| `file.exe.txt` | `.` 있음 | `file`, `exe`, `txt` | `file`, `exe`, `txt` | `exe`가 차단 대상이면 차단 |
| `.env` | `.` 있음 | ``, `env` | `env` | `env`가 정책에 없으면 통과 |
| `abc.` | `.` 있음 | `abc`, `` | `abc` | `abc`가 정책에 없으면 통과 |
| `....abc` | `.` 있음 | ``,``,``,``,`abc` | `abc` | `abc`가 정책에 없으면 통과 |
| `...` (점만 있는 파일명) | `.` 있음 | ``,``,`` | (없음) | 남은 조각 없음 → **차단** |

**보안 관점 메시지 노출 원칙**
- 사용자에게는 **위 표의 "사용자 노출 메시지" 수준의 일반화된 카테고리 메시지만** 보여준다. 어느 검증 단계(크기/확장자/MIME/매직넘버/파서)에서 걸렸는지, 어떤 값이 왜 불일치했는지 등 **검증 로직의 세부 동작을 유추할 수 있는 정보는 노출하지 않는다.**
- "악성코드가 탐지되었습니다"처럼 결과의 성격(무엇이 문제였는지 큰 범주)을 알려주는 수준은 UX상 필요하다고 판단해 허용한다.
- 상세 사유(어느 단계, 어떤 시그니처/값 불일치)는 **서버 로그에만 기록**하고 클라이언트 응답에는 포함하지 않는다.
- 모든 단계를 통과한 파일만 F2-3의 "성공" 처리로 넘어간다.
- 각 단계의 판단 로직·정규화 규칙·라이브러리 선정은 `spec.md`에서 상세 정의한다.

### F2-3. 업로드 결과 응답
- **성공 시**: 파일을 최종 저장 경로(UUID 파일명, 실행 권한 제거)에 저장하고 성공 응답 반환
- **차단 시**: 저장하지 않고, F2-2 표의 "사용자 노출 메시지" 수준으로만 응답한다. **어느 검증 단계에서 차단되었는지, 세부 판단 근거가 무엇인지는 응답에 포함하지 않는다** (보안상 검증 로직 노출 방지). 상세 사유는 서버 로그로만 남긴다.
- **연동 API 응답**: `200 OK` (성공) / `4xx` (정책 위반, 일반화된 사유 메시지 포함) / `5xx` (서버 오류)

## 4. F3. (선택) 정책 변경 이력 조회
- **설명**: 고정/커스텀 확장자 정책이 언제, 무엇이, 어떻게 변경되었는지 이력을 조회한다.
- **구현 여부**: 시간 허용 시 구현, 아니면 `CONSIDERATIONS.md`에 "필요성은 인지했으나 미구현" 근거만 기록
- **연동 API**: `GET /api/policy/history` (구현 시)

## 5. 기능 간 처리 흐름 요약

```
[정책 관리 화면]
  F1-1/F1-3 조회 ─▶ 화면 표시
  F1-2 체크 토글 ─▶ 즉시 DB 저장
  F1-4 추가 ─▶ 클라이언트 검증 ─▶ 서버 검증 ─▶ DB 저장 ─▶ 목록 갱신
  F1-5 삭제 ─▶ DB 삭제 ─▶ 목록 갱신

[업로드 화면]
  F2-1 업로드 요청
    └▶ F2-2 검증 파이프라인 (0.크기[10MB] → 1.확장자 → 2.MIME[로그전용,통과] → 3.MagicNumber[최종판단] → 4.Parser → 5.ClamAV)
          ├─ 실패(0,1,3,4,5 중 하나) ─▶ F2-3 차단 응답 (일반화된 사유 메시지만, 상세는 서버 로그)
          └─ 전부 통과 ─▶ F2-3 저장 + 성공 응답
```

## 6. 기능별 예외 케이스 매핑 (요약)

> 상세 근거는 `CONSIDERATIONS.md`, 검증 규칙 세부값은 `spec.md` 참고.

| 케이스 | 관련 기능 | 처리 방향 |
|--------|-----------|-----------|
| 10MB 초과 파일 업로드 | F2-2 (0단계) | 즉시 차단, 뒷단계(특히 ClamAV) 자원 낭비 방지 (결정 완료) |
| 확장자 없는 파일 (`.`이 파일명에 아예 없는 경우, 예: `Makefile`, `README`) | F2-2 (1단계) | **차단** (결정 완료 — 규칙 1) |
| 점으로 시작하는 파일 (`.env` 등 dotfile) | F2-2 (1단계) | **차단하지 않음.** 선행 빈 문자열은 무시하고 `env`를 일반 확장자 후보로 검사 (결정 완료) |
| 점으로 끝나는 파일 (`abc.`) | F2-2 (1단계) | 후행 빈 문자열 무시, `abc`를 확장자 후보로 검사 (결정 완료) |
| 연속된 점 (`....abc`, `...`) | F2-2 (1단계) | 빈 문자열 전부 무시. 남은 조각이 있으면 후보로 검사, 하나도 없으면(`...`) 확장자 없는 파일로 차단 (결정 완료) |
| 이중/다중 확장자 (`file.exe.txt`) | F2-2 (1단계) | 모든 조각을 확장자 후보로 보고 각각 검사, 하나라도 차단 대상이면 전체 차단 (결정 완료) |
| MIME과 확장자 불일치 | F2-2 (2단계) | **차단하지 않음.** 로그만 기록, 최종 판단은 3단계(Magic Number)에 위임 (결정 완료) |
