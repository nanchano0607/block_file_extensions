# design.md — UI 디자인 & 상태별 화면 반응

> 본 문서는 `function.md`에서 정의한 기능(F1, F2)과 `spec.md`에서 정의한 API/에러 응답을 기준으로,
> 화면 레이아웃과 **상태별(로딩/성공/에러/빈 값 등) UI 반응**을 정의한다.
> 시각적 톤(색상/폰트 등 브랜딩)은 규정하지 않고, **상태 전이와 사용자 피드백 방식**에 집중한다.
> 화면이 2개뿐인 과제 규모를 고려해, 디바운스·오프라인 감지·단계별 보조 안내 등 정교한 처리는
> 넣지 않고 **로딩 → 성공/실패**의 단순한 상태만 다룬다.

---

## 0. 설계 원칙

1. **모든 비동기 동작(저장/추가/삭제/업로드)은 로딩·성공·실패 3가지 상태만 갖는다.** 그 이상의 세분화(디바운스, 오프라인 감지 등)는 하지 않는다.
2. **실패 시 화면 상태는 항상 DB 상태와 일치시킨다.** 낙관적 업데이트(Optimistic UI)를 쓰는 경우, 실패하면 반드시 **이전 상태로 롤백**한다 (function.md F1-2/F1-4/F1-5 예외 처리 원칙과 동일).
3. **에러 메시지는 spec.md에서 정의한 카테고리 메시지를 그대로 노출**하며, 화면에서 임의로 상세화하지 않는다 (보안 원칙 유지).
4. **클라이언트 1차 체크는 성격에 따라 다르게 처리한다.** 파일 크기 초과처럼 서버 호출 자체가 무의미한 경우는 업로드를 막지만(하드 블록), 확장자 차단 여부처럼 최종 판단이 서버에 있는 경우는 경고만 하고 업로드는 막지 않는다(소프트 경고) — function.md F2-1의 "최종 판단은 항상 서버" 원칙을 지키기 위함.

## 1. 정책 관리 화면

### 1-1. 레이아웃 (과제 원본 참고 이미지 기준)

```
◎ 파일 확장자 차단
파일확장자에 따라 특정 형식의 파일을 첨부하거나 전송하지 못하도록 제한

① 고정 확장자   ☐ bat  ☐ cmd  ☐ com  ☐ cpl  ☐ exe  ☐ scr  ☐ js
② 커스텀 확장자  [ 확장자 입력            ] (+ 추가)
③               3/200
                [ sh ✕ ] [ ju ✕ ] [ ch ✕ ]
```

- ① 고정 확장자 영역: 체크박스 7개, 가로 나열
- ② 커스텀 확장자 입력 영역: 텍스트 입력창 + "추가" 버튼
- ③ 커스텀 확장자 목록 영역: 칩(chip) 형태로 나열, 각 칩에 `X` 삭제 버튼 포함, 상단에 `N/200` 카운터 표시. 개수가 많아 화면을 넘으면 이 영역에만 세로 스크롤 적용(페이징 아님)

### 1-2. 화면 최초 진입 (F1-1, F1-3)

| 상태 | UI 반응 |
|---|---|
| 로딩 중 | 고정 확장자 체크박스 영역과 커스텀 확장자 목록 영역에 로딩 표시. 입력창/추가 버튼은 비활성화 |
| 조회 성공 | 체크박스 상태(DB값 그대로), 커스텀 목록, `N/200` 카운터 렌더링 |
| 조회 실패 (네트워크/서버 오류) | 영역 전체에 "정책을 불러오지 못했습니다. [다시 시도]" 인라인 에러 + 재시도 버튼 |
| 커스텀 확장자 0개 (빈 상태) | 칩 목록 영역에 "등록된 커스텀 확장자가 없습니다" 안내 텍스트만 표시 (에러 아님, 정상 빈 상태) |

### 1-3. 고정 확장자 체크/해제 (F1-2)

> function.md에서 이미 확정된 "체크박스 클릭 = 즉시 자동 저장(`PATCH` 단일 API)" 방식을, 본 절에서 화면 반응으로 구체화한다.

| 상태 | UI 반응 |
|---|---|
| 클릭 직후 (저장 요청 중) | 체크 상태를 즉시 반영(낙관적 업데이트)하고, 해당 체크박스 옆에 작은 로딩 표시 |
| 저장 성공 | 로딩 표시 제거. 별도 성공 토스트는 띄우지 않음(체크 상태 자체가 이미 성공을 의미하므로) |
| 저장 실패 | 체크박스를 클릭 이전 상태로 롤백, 근처에 짧은 인라인 에러("저장에 실패했습니다") 표시 |

### 1-4. 커스텀 확장자 추가 (F1-4)

**입력창 상태**

| 상태 | UI 반응 |
|---|---|
| 기본 | placeholder "확장자 입력 (최대 20자)" |
| 입력 중 | 실시간 글자 수 표시(`n/20`), 20자 초과 입력은 입력 자체를 막음(maxlength) |
| 200개 도달 | 입력창과 "추가" 버튼 비활성화, 카운터(`200/200`) 강조 표시, "최대 200개까지 등록할 수 있습니다" 안내 |

**"추가" 클릭 이후**

| 상태 | UI 반응 |
|---|---|
| 요청 중 | "추가" 버튼 로딩 표시로 전환 + 비활성화 (중복 클릭 방지) |
| 성공 | 입력창 비우기, 목록에 새 칩 추가, 카운터 갱신 |
| 실패 — 중복(고정/커스텀) | 입력창 아래 인라인 에러 "이미 등록된 확장자입니다" 또는 "이미 고정 차단 목록에 있는 확장자입니다" (spec.md 메시지 그대로), 입력값 유지 |
| 실패 — 형식 오류(특수문자 등) | 입력창 아래 인라인 에러 "영문/숫자만 입력 가능합니다", 입력값 유지 |
| 실패 — 200개 초과 | 인라인 에러 "커스텀 확장자는 최대 200개까지 등록할 수 있습니다" |
| 실패 — 네트워크/서버 오류 | 인라인 에러 "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요.", 입력값 유지 |

### 1-5. 커스텀 확장자 삭제 (F1-5)

| 상태 | UI 반응 |
|---|---|
| `X` 클릭 직후 | 해당 칩을 즉시 목록에서 제거(낙관적 업데이트) |
| 삭제 성공 | 카운터 갱신, 추가 UI 반응 없음 |
| 삭제 실패 | 제거했던 칩을 원래 위치에 복원 + 인라인 에러 표시 |

## 2. 업로드 화면

### 2-1. 상태 흐름

파일 크기 초과와 확장자 차단은 성격이 다르므로 분리한다. 크기 초과는 서버 호출 자체가 무의미해 업로드를 막지만(하드 블록), 확장자는 클라이언트가 들고 있는 정책이 최신이 아닐 수 있어(예: 관리자가 방금 정책을 바꿈) 경고만 하고 최종 판단은 서버에 맡긴다(소프트 경고, 업로드 버튼은 계속 활성).

```
[Idle: 파일 미선택]
   └▶ 파일 선택
[Selected: 파일 선택됨]
   ├─ 크기 10MB 초과 ─▶ [SizeRejected] (업로드 버튼 비활성화, 서버 호출 안 함, 재선택만 가능)
   ├─ 확장자가 현재 조회된 정책상 차단 대상으로 보임 ─▶ [ExtensionWarning]
   │     (경고 문구만 표시, 업로드 버튼은 그대로 활성 — 최종 판단은 서버)
   └─ 이상 없음 / 경고 무시하고 진행 ─▶ 업로드 버튼 클릭
              └▶ [Uploading: 서버 전송 및 6단계 검증 중]
                    ├─ 성공 ─▶ [Success]
                    ├─ 정책 위반(4xx) ─▶ [Blocked]
                    └─ 서버 오류(5xx) ─▶ [ServerError]
```

### 2-2. 상태별 UI

| 상태 | UI 반응 |
|---|---|
| Idle | "파일 선택" 버튼. 안내 문구: "최대 10MB" |
| Selected | 선택된 파일명/크기 표시, "업로드" 버튼 활성화 |
| SizeRejected (10MB 초과) | 인라인 에러 "파일 크기 제한을 초과했습니다" — **서버 호출 없이** 클라이언트에서 즉시 표시. 업로드 버튼 비활성화, 다른 파일 재선택만 가능 |
| ExtensionWarning (정책상 차단 대상으로 보임) | 경고 문구 "현재 정책상 차단된 확장자일 수 있습니다" 표시. 업로드 버튼은 **비활성화하지 않음** — 사용자가 그대로 업로드를 시도하면 서버가 최종 판단 |
| Uploading | 로딩 표시 + "업로드 중..." 텍스트. 업로드 버튼 비활성화(중복 클릭 방지). 6단계 검증의 개별 진행 상황은 노출하지 않는다(보안 원칙 — 어느 단계인지 노출 금지) |
| Success | "업로드에 성공했습니다" + 업로드된 파일명. "새 파일 업로드" 버튼으로 Idle로 복귀 |
| Blocked (4xx, 정책 위반) | spec.md의 카테고리 메시지 그대로 노출(예: "허용되지 않는 파일 형식입니다", "악성코드가 탐지되었습니다") + "다른 파일 선택" 버튼. 단계별 상세 사유는 노출하지 않는다 |
| ServerError (5xx) | "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요." + "다시 시도" 버튼 |

> ClamAV 단계는 결과에 따라 이 두 상태로 갈린다: 실제 악성코드가 **탐지**되면 `Blocked`(422), 반면 ClamAV 연결 실패·타임아웃처럼 스캔 자체를 **완료하지 못하면** `ServerError`(500)로 처리한다(spec.md 4-5).

## 3. 공통 UI 컴포넌트

| 컴포넌트 | 용도 |
|---|---|
| 인라인 에러 텍스트 | 입력창/체크박스 등 특정 항목 단위의 실패, 해당 항목 근처에 표시 |
| 로딩 인디케이터 | 버튼·체크박스·목록 조회 등 진행 중 표시. 정책 화면/업로드 화면 동일한 방식 하나로 통일 |

---

## 4. 접근성/반응형 (선택 항목)

과제 평가상 선택 사항이므로, 시간이 부족하면 기본 시맨틱 HTML(적절한 `<button>`, `<input>`, `<label>` 사용)만 지키는 최소 수준으로 구현하고 `CONSIDERATIONS.md`에 "심화 접근성/반응형은 시간 관계상 미구현"으로 기록한다. 시간이 남으면:

- 체크박스/입력창/버튼은 Tab 순서로 접근 가능, 삭제(`X`) 버튼도 포커스 가능한 버튼 요소로 구현
- 에러 메시지는 `aria-live="polite"`로 선언
- 고정 확장자 체크박스 7개, 커스텀 확장자 칩 목록 모두 좁은 화면에서 자동 줄바꿈

## 5. 문서 간 연계 확인

- 1-3(F1-2 자동저장 UI), 2-2(카테고리 메시지 노출)는 `function.md`에서 이미 확정된 원칙(자동저장 방식, 메시지 노출 최소화)을 **본 문서에서 실제 화면 반응으로 구체화**한 것이다. 새로운 정책 결정이 아니라 기존 결정의 UI 반영이며, 상충되는 부분이 생기면 `function.md`/`spec.md`를 함께 갱신한다.
- 에러 메시지 문구는 전부 `spec.md` 3장(API 명세)의 값을 그대로 사용하며, 이 문서에서 새로운 문구를 임의로 만들지 않는다.
